## 8. GO / NO-GO Decision Framework

**GO** if: 10 criteria pass + 5 gates approved + 20p room 10-min stable + SFrame payload-opaque routing proven OR documented fallback (all-layers-for-≤20p trade-off shipped, not facaded) + @reviewer signs “honest E2EE”.

**NO-GO triggers (any one):**
- Safari SFrame impossible without silent downgrade (criterion 1/4 fails)
- 20p + SFrame forwarding contradiction unsolved even with all-layers mode (crit 2/4)
- Key rotation p95 >500ms after optimization OR keys not zeroized
- Reconnect p95 >5s consistently on 2+ browsers
- Lighthouse <95 due to WASM 150KB + bundle >120kB irreconcilable (requires re-architect, not tuning)
- TURN relay leaks plaintext or fails under strict NAT

**On NO-GO:** 48h pivot proposal due from @architect + @webrtc + @reviewer: Option A) Mesh-E2EE capped 5p + non-E2EE SFU for >5 (explicit consent, no facade), Option B) De-scope E2EE to 1:1 only, Option C) Replace LiveKit with mediasoup. PM schedules stakeholder decision within 1 week. Zoom feature freeze remains until new P0 passes.

## 9. Risks & Mitigations (P0-specific, per Reviewer §8)

1. **SFrame + Dynacast/Last-N contradiction** → SFrame header-aware but payload-opaque routing; if LiveKit Dynacast reads need payload, ship blind-forward 3 layers for ≤20p (80% downlink cost accepted for P0 honesty). No facade.
2. **H264 E2EE unreliable** → VP9 SVC first, H264 baseline fallback; WASM latency +15ms budgeted.
3. **Safari Insertable Streams gap** → WASM polyfill + `OffscreenCanvas` + `VideoFrame` recycle; degrade to DTLS-only with hard warning if unavailable — never silent.
4. **20p client decrypt contention** → Cap E2EE at proven limit; webinar 1000p NOT in P0 (frozen).
5. **MLS central KMS backdoor** → Remove central KMS; per-room sender-key ratchet, DataChannel broadcast + epoch.
